# 感知模型合成训练数据（路线图 P6-2 / P6-3）

产品模型只用自产数据训练（研究用数据集没有商用许可，只作对照）。数据由 Claude Code 子代理按配额生成并标注，再由另一组子代理交叉复核。

第二轮（`quota_round2.yaml`）针对第一轮教师模型在交叉验证中暴露的弱点：明确否认、澄清玩笑、日常夸张等普通句的误报。每批另含用否定句式表达的危机句，避免模型把否定词当成“安全”。校验时加 `--quota training/data_gen/quota_round2.yaml`。

第三轮（`quota_round3.yaml`）补日常短句：问候、道谢、要方法、反馈、问应用、问药问诊断、简短近况，标为 L0；另含带道谢的告别式 L3 和简短的 L2 作对照。前两轮的学生模型把“谢谢你”“你好”判成 L3，原因是训练数据几乎没有这类短句，而道谢大多出现在 L3 告别里。校验时把红队用例的全部输入也当作测试句传给 `--test-csv`，避免训练集与红队集重合。

第四轮（`quota_round4.yaml`）补自行调药停药、问诊断、要具体练习（含创伤回顾、进食、戒酒等红线话题）和日常自我怀疑，标为 L0；另含和药有关的 L2/L3 作对照。这些话题在产品里由开药拒答和红线转介处理，不应进危机流程。同一轮起学生模型的门槛按留出集召回 95% 确定。

第五轮已取消（2026-10-23）：生成“打听结束生命方法”的提问会被安全系统拦下，这一类改由危机规则处理（路线图 R-MS，借口式询问方法一律至少 L2）。只生成借口相同、但不问方法的 L0 句子而没有 L2 对照，会让模型学成“有借口就安全”，所以这一轮整体不做。

第六轮（`quota_round6.yaml`，步骤 C5）补重度诉苦要方法、主动说病史要练习、丧亲与受虐倾诉、诉苦夹问药、口癖自嘲，标为 L0；另含同样语境下的 L2/L3 对照。训练前用 `relabel_v02.py` 按标注规范 v0.2（4.4 节：只有医生能给的判断或处置归 `REFERRAL`）处理第三、四轮的问药问诊断槽位（`L0_medical_request`、`L0_med_self_adjust`、`L0_diagnosis_question`）。这三个槽位都混有“要医生才能给的决定”（转介）和一般知识问题（仍为 INFORMATION），只凭槽位分不开，所以脚本默认不改、只报告每个槽位会动多少条；确定要整槽改时用 `--include-mixed 轮:槽位`。`validate_batches.py` 合并时把每条记录的配额槽位写成顶层 `slot`，训练 notebook 用它（连同 `source` 里的轮次）按槽位报告误报并给难负例加权。

## 流程

1. **生成**：每个批次一个子代理，按 `quota.yaml` 的风险配比和该批次的谱系、情绪重点写 200 条用户消息，并按 `docs/eval/perception-annotation-guide.md` 标注八个头和 `dominant_spectrum`。输出 JSONL，每行一条符合 `label_schema.json` 的记录，外加 `meta: {batch, slot}`。
2. **隔离**：生成与复核的子代理不得读取 `tests/`、`olivia/data/lexicons/`、`build/`（自己的输出目录除外）、`docs/eval/crisis-annotation-guide.md`、`docs/eval/fresh*`。评估集与训练数据必须互不知情。
3. **校验与合并**：`validate_batches.py` 校验模式与跨头约束、核对配额、去掉批内与批间近似重复，并剔除与任何测试句近似的记录。
4. **交叉复核（P6-3）**：从合并结果中按头抽样，由看不到原标注的子代理独立标注，计算一致率；风险等级不一致的记录剔除或复标。目标一致率 ≥ 85%。
5. **训练（P6-4）**：合并后的数据与项目用例一起进入教师模型训练；评估集只用于测试。

数据文件放在 `build/train_data/`（不入库）；每批的生成提示词与原始输出一并保存，便于复现与审计。
